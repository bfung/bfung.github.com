# AGENTS.md

Working instructions for this repository — Benson Fung's personal site.

## Overview

- Static site built with Eleventy 3 (ESM config in `eleventy.config.js`).
- `src/` is the source; `docs/` is the generated output that GitHub Pages serves.
- One shared layout: `src/_includes/base.njk`. Global site data (name, canonical URL): `src/_data/site.json`.
- Root passthrough files: `robots.txt`, `.nojekyll` (Pages serves the site as plain static files, not Jekyll).

## Development & operations

- Install: `npm install`
- Local preview: `npm run dev` (Eleventy dev server with hot reload)
- Build: `npm run build` — writes to `docs/`
- **Always commit the generated `docs/` output alongside source changes.** Pages deploys from `docs/` on `master`; a source-only commit leaves the live site stale.
- **Never hand-edit files in `docs/`.** Change `src/` and rebuild.
- After editing, run `npm run build` and sanity-check the changed `docs/*.html` before committing.
- Push to `master`; Pages redeploys automatically from `docs/`.

## Analytics — Datadog RUM (the site's only analytics)

- Config lives in exactly one place: `src/assets/js/rum-init.src.js` (`service: bfung.github.io`, `env` always `prod`, Datadog site `us3`, `version` = `package.json` version). Change config there; do not duplicate the application ID / client token elsewhere in the repo — they are public browser identifiers and that file is the source of truth.
- **Edit the `.src.js`, never the bundle.** `src/assets/js/rum-init.js` is generated by `npm run bundle:rum` (esbuild bundles `@datadog/browser-rum` into a minified IIFE). `npm run build` and `npm run dev` both run `bundle:rum` first. If the bundle is missing or stale in `docs/`, rerun the build; never hand-edit it.
- **Wiring:** `src/_includes/base.njk` loads the bundle in `<head>` with `defer` and the `cacheBust` filter — that covers all 9 main pages. The 16 standalone vibe-redesign templates each load it with a hardcoded `?v=<version>` query instead. **When `package.json` version changes, update that query in all 16 vibe files** (base.njk needs no manual bump) and keep the RUM `version` in step too.
- **Tracking:** multi-page static site, no client router, so default RUM view tracking gives one view per page load and `trackUserInteractions` covers link clicks. No custom views or actions. Known gaps — do not silently fix, use `data-dd-action-name` only if naming matters later: FamilyTreeMe SVG-node clicks, the project-sort `<select>` change event (not a click), and generic names on button clicks (theme/nav toggles, filter chips).
- **Privacy:** no PII on the site (no email, phone, or zip; FamilyTreeMe uses kinship titles only), no CSP, no other analytics. Session replay samples only public content. RUM beacons to Datadog `us3` are the deliberate exception to the site's otherwise no-third-party-loads rule (previously only Google Fonts + jsDelivr).
- **Quick check after a build:** `docs/assets/js/rum-init.js` exists and every built HTML page references it; in Datadog, events should show `service: bfung.github.io`, `env: prod`, and `version` matching `package.json`.

## Site style and design

- CSS architecture: cascade layers — `reset`, `base`, `theme`, `components`, `utilities` — in `src/assets/css/style.css`. Keep new styles in the correct layer; component styles belong in `components`.
- Theming: color comes from CSS custom properties in the `theme` layer. Light and dark modes switch via the `data-theme` attribute on `<html>`; `src/assets/js/main.js` defaults to the OS `prefers-color-scheme` and persists an explicit user choice in localStorage. New UI must work in both themes.
- Color: OKLCH palette — deep indigo accents in light mode, teal-blue accents in dark mode.
- Typography: Outfit for headings, Inter for body, each with system-ui fallbacks. No icon fonts; use inline SVG where icons are needed.
- Layout: fluid, responsive, mobile-first. The resume page has a dedicated print stylesheet — keep print output clean.
- Accessibility: semantic HTML, skip-to-content link, real `alt` text on images, keyboard-reachable controls.
- SEO basics live in the shared layout: canonical URL, Open Graph + Twitter cards, JSON-LD Person schema, `sitemap.xml`, `robots.txt`. Keep metadata current when URLs or page purposes change.

## Conventions

- Pages are Nunjucks templates (`.njk`) with front matter (`title`, `description`) consumed by the layout.
- **Content is single-sourced in `src/_data/`**: `profile.json` (title, taglines, summary, location, socials), `resume.json` (experience, education, skills), `projects.json`, `guides.json`. The main Home/Resume AND all eight VibeRedesign designs render from these files — edit the data, never the templates, to change content. Vibe templates loop over the data in their own markup; never use Nunjucks `selectattr` to pick a social (it silently does not filter here) — loop and match on `s.id` instead.
- Assets live under `src/assets/` and are passthrough-copied to `docs/assets/`.
- Reference global data from `src/_data/site.json` rather than hardcoding the site URL in templates.
- Commit and push promptly after a change is verified — uncommitted work in this checkout was once lost mid-session (working tree reverted to HEAD with no trace), so don't leave changes uncommitted across long detours.
- Keep braces balanced in `style.css`: a single stray `}` once caused the CSS parser to silently drop the entire `@layer utilities` block (visible skip link, dead `.sr-only`). After structural CSS edits, verify the parsed stylesheet in the browser (e.g. check `document.styleSheets` layer blocks), not just the source.
